# Finance HOL 类型标注

按 HOLogicBench 的 PR、PT、PC、PS、PQ 分类，对 `data/sample1.json`、`sample2.json`、`sample3.json` 中全部 **1,079** 条当前有效样本标注。审稿包仅保留原始案例表示，已删除重复的 enriched 文件。sample3 的 ID 范围为 1–719，但不包含 313–352，实际为 679 条。

## 字段与使用

- `hol_types`：命中的标签列表，顺序固定为 PR、PT、PC、PS、PQ；允许多标签或空列表。
- `hol_type_flags`：五个标签各自的布尔值，每条 case 都包含全部五项。
- `hol_type_annotation`：标注版本、层级及逐项依据。每条依据含类型、子案例名称、Isabelle 定义名、中文解释和相关条件。
- `data/hol_type_summary.json`：按样本集统计的标签数量及标签组合。

标注版本为 `finance-policy-semantics-v1`，层级为 `policy_semantics`。依据来自 `groundtruth/baoxiao_rules.thy` 和每条 case 的 `isabelle_case_conditions_nl`。这些标签表达**任务中的政策推理语义**，并非声称源代码已经实现 `Policy → Policy` 等高阶操作的类型签名。现有实现主要把选择、组合和例外展开为一阶记录上的谓词、条件分支与数值运算。若论文要求直接以政策为参数或返回值的形式化 HOL 证据，仍须另行重构并证明对应编码。

## 判定口径

| 标签 | 判定方式 | Finance 中的依据 |
| --- | --- | --- |
| PR | 明确使用两个政策的优先关系 | 合同交通规则优先于常规交通等级政策；仅在 `has_contract_specific_transport_rule` 为真时标注 |
| PT | 案例触发对基础政策的限额调整、范围收紧或例外审查 | 超标准交通、无法取得票据、外部承担交通和住宿后取消补贴、境外购物无正式票据、会议不安排食宿时扣减额度、培训超30天后定额降至70%、重大外交活动陪同人数例外、未清借款的特殊理由例外 |
| PC | 将分别定义的政策谓词合并为同一审核政策，或同一申请受两个明确关联的政策约束 | 规则3、6–11、13、14、18–20中的命名子政策组合；发票与办公/维修联合审核；规则19主动关联规则7或9 |
| PS | 由费用类别、身份、资金来源、地域或阶段选出适用的政策分支 | 差旅人员与资金类型、会议类别、培训人员级别、探亲关系、评审/讲课/咨询类别、工程支付阶段、质保/审价业务、资产类型、接待范围及借款核销地域 |
| PQ | 对政策变量或政策集合做量化，并验证政策级性质 | 当前案例未发现此类任务，因此全部为 false |

PC 将命名子政策 `P(x)` 与 `Q(x)` 的联合判断视为 `Compose(P,Q)(x)` 的语义展开；不会将任意两个布尔事实自动视为两个政策。PS 将有明确政策分支含义的上下文判断视为 `Select(c)` 的语义展开；不会仅因 case 属于某个费用大类而套用全局路由标签。PT 将例外或定额调整解释为基础政策变换；固定表格中的职级/地区标准选择归为 PS。

标签描述完整审核任务所涉及的操作，不模拟求值器因某项失败而提前返回的最短路径。PT 表示需要审查例外或调整条件，不表示例外最终获批。case 中有多个子案例时取标签并集；多个独立人员或费用的批量审核本身不额外产生 PC 或 PQ。

规则19记录包含预置的规则7、9嵌套记录。只有关联条件成立时，才使用嵌套记录的标签，避免把未使用的默认数据计入。规则4纯发票完整性检查的20条独立案例没有政策对象层面的对应操作，保留空标签及五项 false；不强行归类。现有模型结果、历史版本和派生 `case_index.json` 不作为本次独立案例集合，也未改写。

## 重建与验证

从仓库根目录运行：

```sh
python3 finance/scripts/add_hol_types.py
python3 finance/scripts/add_hol_types.py --check
```

脚本在写入前检查三个原始文件与对应 enriched 文件的 ID 集合及标注一致性；未知条件结构会报错。`--check` 不写文件，会重新计算并核对全部标签、依据和汇总。修改样本或规则后应重新审查映射并运行脚本。
